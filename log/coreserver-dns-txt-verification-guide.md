# CORESERVER利用者向け：DNSのTXTレコードでドメインを確認する手順

更新日：2026年10月20日

Web Security Inspectorの「DNSの管理画面で次のTXTレコードを追加してください。サブドメインは個別に確認します。」に対応する手順です。CORESERVERで公開しているサイトを、バリュードメインのDNSで管理している場合を中心に説明します。

## 1. 最初に確認すること

**作業する場所は、診断対象ドメインの現在のDNS管理画面です。** CORESERVERはWebサイトを置くサーバーで、DNSの管理先は別の場合があります。VercelのEnvironment VariablesやGitHubの設定には、今回のTXTレコードを登録しません。

1. ドメインを契約しているサービスにログインし、対象ドメインの「ネームサーバー」設定を確認します。
2. バリュードメインのDNSを使用している場合は、この手順の「3」へ進みます。
3. 他社DNSを使用している場合は、そのサービスのDNS管理画面で同じTXTレコードを追加します。CORESERVERを使っていることだけを理由に、バリュードメイン側で設定しても反映されません。

今回の確認のためにネームサーバーを変更する必要はありません。既存のA・AAAA・MX・CNAME・メール用TXTレコードも、そのまま維持します。設定前に、現在のDNSレコードをエクスポートするか、内容をコピーして控えてください。

バリュードメインの無料ネームサーバーで他社取得ドメインを管理している場合は、登録済みの「無料ネームサーバー」の管理画面から対象ドメインのDNS設定を開きます。今回の作業で無料ネームサーバーを新規作成したり、DNSを移行したりする必要はありません。[無料ネームサーバーの公式説明](https://www.value-domain.com/userguide/manual/freedns)

## 2. アプリでホスト名と値を確認する

1. [Web Security Inspector](https://web-security-inspector-sepia.vercel.app)を開きます。
2. 「自分のドメインを診断」で、GitHubにログインします。
3. 「自社のドメインまたはURL」に、診断したいドメインを入力します。例：`example.com`。
4. 管理権限と診断の許可を確認してチェックを入れ、「確認コードを発行」を押します。
5. 対象ドメインの欄に表示される「ホスト名」と「値」を控えます。すでに表示されている場合は、その内容を使います。

`example.com`を登録した場合、次の形式になります。

```text
種類：TXT
ホスト名：_wsi.example.com
値：wsi-verification=<アプリ画面に表示された64文字の確認コード>
```

`<アプリ画面に表示された64文字の確認コード>`は説明用の表記です。実際には、アプリの「値」のコピーボタンを使い、`wsi-verification=`から末尾までをコピーしてください。山括弧や説明文は入力しません。

確認コードは、ログインしたアカウントと登録ドメインごとに異なります。別のドメイン用の値や、この手順書の例をそのまま使うことはできません。

## 3. バリュードメインのDNS設定を開く

[バリュードメインのログイン画面](https://www.value-domain.com/login.php)を開きます。ログイン先がバリュードメイン Oneに移動する場合もあります。

表示される画面に合わせて、AまたはBのどちらかを行ってください。

### A. 「ドメイン管理」「DNS設定」がある画面

1. 「ドメイン」→「ドメイン管理」を開きます。
2. DNSを編集する対象ドメインを選びます。通常、`www.example.com`の確認でも、ここでは親ドメインの`example.com`を選びます。
3. 「DNS設定」→「edit（編集）」を押します。
4. レコードの追加ボタンで、新しい行を追加します。
5. 「4-A」の内容を入力します。

[公式マニュアル：DNS設定](https://manual.value-domain.com/manual/domain/dns)

### B. 「ドメインの設定操作」「DNS/URL」がある従来の画面

1. 「ドメイン」→「ドメインの設定操作（登録済みドメイン一覧）」を開きます。
2. 対象ドメインの「DNS/URL」を押します。
3. DNSレコードのテキスト入力欄を開きます。
4. 既存の内容を残し、末尾に「4-B」の行を追加します。

今回の作業では、サーバーの自動設定やテンプレートによる一括設定は使わず、確認用TXTレコードだけを追加します。欄が分かれた入力画面の場合は「4-A」を使ってください。

[公式マニュアル：DNS情報・URL転送の設定](https://www.value-domain.com/userguide/manual/moddns)

## 4. TXTレコードを追加して保存する

以下は、`example.com`のDNS設定を編集し、アプリで`example.com`の確認コードを発行した場合の例です。

### 4-A. 「タイプ・名前・コンテンツ」の入力欄がある場合

追加した行に、次の内容を入力します。

- **タイプ**：`TXT`
- **名前**：`_wsi`
- **コンテンツ**：アプリの「値」をそのまま貼り付けます。`wsi-verification=`を含む文字列全体です。
- **TTL**：通常は画面の既定値を維持します。
- **PRIORITY**：TXTでは使用しません。

「名前」に`_wsi`と入力すると、`example.com`のDNS設定では、完成する名前は`_wsi.example.com`になります。アプリの完全なホスト名をそのまま貼るとドメイン名が二重になる入力方式もあるため、完成する名前がアプリ表示と一致することを確認します。ホスト名の詳しい対応は「6」を参照してください。

値の前後に引用符や空白を自分で追加せず、「保存」を押します。「DNSレコードを保存しました」など、保存完了の表示を確認してください。[入力項目の公式説明](https://manual.value-domain.com/manual/domain/dns)

### 4-B. DNSレコードをテキストで記述する場合

既存の設定を残し、末尾に改行して、次の形式で1行追加します。

```text
txt _wsi wsi-verification=<アプリ画面に表示された64文字の確認コード>
```

`<...>`部分を実際の確認コードに置き換えてください。先頭の`txt`と名前`_wsi`は半角スペースで区切り、3番目の部分にはアプリからコピーした「値」を入れます。実際の入力に山括弧や説明文は含めません。

「保存」または「変更」を押し、保存完了の表示を確認します。既存のSPF・DKIM・DMARCなどのTXT行を、この行に置き換えないでください。

従来画面の`txt 名前 値`という記述形式は、[バリュードメインの公式設定例](https://www-admin.value-domain.com/information/detail/?no=20230607-2)でも確認できます。

## 5. DNSへの反映後、アプリで確認する

1. 保存後、しばらく待ちます。バリュードメインの公式案内では反映に5〜30分程度かかる場合があります。DNSキャッシュなどの状況により、それ以上かかる場合もあります。[反映時間の公式案内](https://www.value-domain.com/userguide/manual/moddns)
2. Web Security Inspectorの画面に戻ります。
3. 対象ドメインの「DNSを確認」を押します。
4. 「確認済み」と「DNSレコードが一致しました。このドメインを診断できます。」が表示されたら完了です。
5. 「診断対象のURL」に、その確認済みドメインのURLを入力します。例：`https://example.com/`。
6. サイトの所有権または診断の許可を確認してチェックを入れ、「診断を開始」を押します。

「DNSを確認」はTXTレコードを照合する操作で、サイトの診断は別の操作です。確認に失敗しても連打せず、入力内容と反映状況を確認してから再実行してください。

**アプリを利用する間は、確認用TXTレコードを残してください。** 診断のたびにTXTレコードを確認するため、削除後はDNSキャッシュの更新などに伴い診断できなくなります。

## 6. サブドメインを確認する場合

`example.com`、`www.example.com`、`shop.example.com`は、アプリでは別々の診断対象です。`example.com`が確認済みでも、`www.example.com`や`shop.example.com`は自動で確認済みになりません。

通常の構成では、DNSは親ドメイン`example.com`の設定画面で編集し、アプリでは各ホストを個別に登録します。入力例は次のとおりです。

### `example.com`を確認する

- アプリに登録するドメイン：`example.com`
- アプリに表示されるホスト名：`_wsi.example.com`
- `example.com`のDNS画面の「名前」：`_wsi`
- 値：`example.com`用にアプリが発行した値

### `www.example.com`を確認する

- アプリに登録するドメイン：`www.example.com`
- アプリに表示されるホスト名：`_wsi.www.example.com`
- `example.com`のDNS画面の「名前」：`_wsi.www`
- 値：`www.example.com`用にアプリが発行した値

従来のテキスト形式では、次の行になります。

```text
txt _wsi.www wsi-verification=<www.example.com用の確認コード>
```

### `shop.example.com`を確認する

- アプリに登録するドメイン：`shop.example.com`
- アプリに表示されるホスト名：`_wsi.shop.example.com`
- `example.com`のDNS画面の「名前」：`_wsi.shop`
- 値：`shop.example.com`用にアプリが発行した値

親ドメイン用のコードを使い回さず、各ドメインの「DNSを確認」をそれぞれ押してください。現行アプリで登録できるドメインは、1アカウントにつき最大3件です。

サブドメインを独立したDNSゾーンとして別のネームサーバーへ委任している構成では、そのゾーンのDNS管理画面で追加します。例えば、編集するゾーンが`shop.example.com`なら、名前は`_wsi`です。**入力する短い名前は、編集しているDNSゾーンによって変わります。最終的な完全名がアプリの表示と一致することが基準です。**

## 7. 「TXTレコードが一致しません」と出る場合

次の順に確認してください。

1. **DNSの管理先**：現在使っているネームサーバーのDNSを編集したか確認します。ドメインの取得先やWebサーバーの契約先だけでは判断できません。
2. **保存**：入力後に「保存」「変更」を押し、完了表示を確認したかを確認します。
3. **ホスト名**：`_wsi`の先頭のアンダースコア、サブドメイン部分、ドメイン名の二重入力を確認します。例えば、`www.example.com`の確認先は`_wsi.www.example.com`です。
4. **値**：`wsi-verification=`から末尾まで、現在のアプリ表示と完全に一致しているか確認します。余分な空白・改行・引用符・説明文を入れていないかを確認します。
5. **反映待ち**：保存直後なら、時間を置いて再実行します。ブラウザの再読み込みだけではDNSキャッシュは更新されません。
6. **アカウント**：確認コードを発行したときと同じGitHubアカウントでログインしているか確認します。
7. **初回確認期限**：現行アプリの初回確認期限は発行から7日です。画面の期限が切れている場合は、アプリから対象ドメインを削除し、登録し直します。再発行された値で、DNSの該当レコードも更新してください。

「DNSを確認できませんでした」と出る場合は、一致・不一致の判定自体が完了していません。少し待って再実行し、続く場合はDNSサービスの障害情報や運営者側の接続状況を確認してください。

### 任意：コマンドで公開DNSを確認する

コマンド操作ができる場合は、次のように確認できます。`example.com`を実際のドメインに置き換えます。

```sh
# 現在のネームサーバーを確認
nslookup -type=NS example.com

# アプリに表示された完全なホスト名のTXTレコードを確認
nslookup -type=TXT _wsi.example.com
```

`www.example.com`を確認する場合は、2つ目のコマンドの問い合わせ先を`_wsi.www.example.com`に変更します。結果に、アプリと同じ`wsi-verification=...`が含まれているかを見ます。表示上の引用符はDNSツールによる表記なので、それだけで設定ミスとは限りません。手元で見えてもアプリ側のDNSキャッシュが追いついていない場合は、時間を置いて再確認します。

## 8. 利用をやめる場合

1. Web Security Inspectorから、対象ドメインの登録を削除します。
2. DNS管理画面で、そのドメイン・そのアカウント向けに追加した`wsi-verification=...`のTXTレコードだけを削除して保存します。
3. 他の利用者が使っている確認用TXTや、メール・他サービス用のTXTは残します。
